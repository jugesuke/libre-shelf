# デザイン

画面を作るときに守るデザインのルールである。各画面の仕様はこの文書の節を参照する。

ここに書いていない見た目（角丸、影、部品の内側の余白など）は、`ui/src/theme.css` の CSS の変数と、`ui/src/components/` の部品の実装に従う。デザインシステムの文書（Storybook）は `ui/src/design-system/` にある。

## 目指すもの

- わかりやすい: 直感的に使えるようにする。同人活動と関係のないことを、できるだけ覚えなくて済むようにする
- たのしい: 余暇の活動である同人活動を妨げないようにする。表示は平易で堅くない雰囲気にする

## 色

### プライマリカラー

プライマリカラー（`--primary`）はその画面の主要な操作に使う色である。値は画面ごとに変え、いまどの画面にいるかの目印にもする。画面ごとの値は [../ナビゲーション.md](../ナビゲーション.md) の「色」にある。

プライマリカラーを使うのは、次の箇所だけである。ほかの箇所にも使うと、目印として目立たなくなるためである。

- メニューで選んでいる項目と、本文の上端の帯
- primary のボタンの背景色
- セグメントコントロールの選んでいる項目の背景色と、タブの選んでいる項目の下線
- 白い背景に置く大きな数字（即売会のレジの合計金額など）

## タイポグラフィ

フォントは BIZ UDPゴシックを使う。太さは標準（400）と太字（700）の 2 種類である。

文字の大きさと太さは、次の 6 つのテキストスタイルから選ぶ。部品がテキストスタイルを持っているときは、部品のものを使う（ボタンのラベル、テーブルの見出しの行など）。

| テキストスタイル | 大きさ | 太さ | 使う箇所 |
|---|---|---|---|
| 見出し（大） | 24px | 太字 | ページの見出し |
| 見出し（中） | 18px | 太字 | セクションの見出し、ダイアログの見出し |
| 見出し（小） | 16px | 太字 | カードの見出し |
| 本文 | 14px | 標準 | 文章、テーブルのセル、入力欄に入れた文字、アラート |
| ラベル | 14px | 太字 | ボタン、入力欄の名前、テーブルの見出しの行 |
| 補足 | 12px | 標準 | 見出しの補足、入力欄のエラー、バッジ |

- 本文の中で強調するときは、大きさを変えずに太字にする。選んでいるタブや、確認のダイアログの対象の値がこれに当たる
- 即売会のレジの合計金額のように大きく見せる数字には、この表にない大きさを使ってよい
- 補足の 12px はボタンには使わない

## 余白

余白は、4px、8px、12px、16px、24px、32px の 6 段階から選ぶ。関係の近い要素ほど狭く、遠い要素ほど広く空ける。

| 用途 | 使う値 |
|---|---|
| 部品の内側（ボタンや入力欄の内側、アイコンと文字の間） | 4px、8px、12px |
| 関係の近い要素の間（ラベルと入力欄、同じセクションの中の行） | 8px、12px、16px |
| セクションとセクションの間、カードの内側 | 16px、24px |
| ページの外側 | 画面の幅が 768px 未満で 12px、768px 以上で 24px |

## 文言と書式

### アラートの文言

アラートの文言には、何が起きたかと、次に何をすればよいかを簡潔に書く。ボタンの横に置くアラートでも、浮かせて重ねるアラートでも、2 行に収まる長さにする。サーバの応答などの技術的な中身は画面に出さず、ブラウザのコンソールに出す。アラートの文言は文なので、最後に句点（。）を付ける。

### 金額

「¥」を前に付け、3 桁ごとにカンマを入れる。

| 書き方 | 例 |
|---|---|
| 金額 | ¥1,000 |
| 0 円 | ¥0 |
| 負の金額（レジ金の不足など） | -¥1,000（「-」は「¥」の前） |

## ボタン

primary のボタンは 1 つの画面（ダイアログを含む）に 1 つまでとする。2 つあると、どちらが重要か分からなくなるので、2 つ目からは secondary にする。

## 処理の失敗

入力の検証は通ったが、処理ができなかったとき（書き込みや通信に失敗したなど）は、操作したボタンの近くに destructive のアラートを出す。アラートが出ても、ほかの要素の位置はずらさない。そのため、ボタンの左に空いた幅があるかどうかで、出し方を分ける。ここでいう行は操作したボタン（ボタンがないときは入力欄）と同じ高さに並ぶ要素のまとまりで、カードのヘッダーではヘッダー全体を指す。

| ボタンの置き場所 | 出し方 |
|---|---|
| ボタンの左に空いた幅がある（フォームの下の右寄せのボタン、右寄せのボタンだけの行） | ボタンの左に、アラートをそのまま置く |
| ボタンの左に空いた幅がない（左に入力欄や見出しがある行、カードのヘッダー） | 行のすぐ下に、アラートを浮かせて重ねる |
| ダイアログの下部のボタン | 下部のボタンの行のすぐ下に、アラートを浮かせて重ね、ダイアログの枠の外へはみ出させる |
| ボタンがない（バーコードの読み取りなど、入力で処理する欄） | 入力欄の行のすぐ下に、アラートを浮かせて重ねる |

### ボタンの左に置くとき

- ボタンの行の高さは、失敗がないときも、2 行のアラートが入る高さ（56px）を取っておく。ボタンは行の上下の中央に置く
- アラートはボタンの左の空いた幅いっぱいに置く。ボタンとの間は 12px にする
- 影、三角、閉じるボタンは付けない。出たときにスクリーンリーダーで読み上げる
- もう一度実行したら、押した時点でアラートを消す。また失敗したら、出し直す

### 浮かせて重ねるとき

- 幅は操作した要素がある行と同じにし、左右の端を行の端にそろえる。ダイアログでは下部のボタンの行と同じ幅にする
- 行のすぐ下に出す（行の下端と三角の先の間は 4px）。アラートの上の縁から、操作したボタン（ボタンがないときは入力欄）の左右の中央へ向けて、三角（吹き出しの口）を付ける。ダイアログでは下部の最後のボタン（主要な操作）に向ける
- アラートには影を付け、下にあるものの上に重ねる。カードやダイアログの枠で切れないように表示する
- 閉じるボタンを付ける。次のどれかで消す。また失敗したら、出し直す
  - 閉じるボタンを押したとき
  - アラートにフォーカスがあるとき、またはアラートを出した画面やダイアログの中にフォーカスがあるときに、Esc キーを押したとき
  - もう一度実行して、押した時点
- 出たときにスクリーンリーダーで読み上げる（`role="alert"`）

## 成功

操作の結果そのものが画面に出るときは、何も出さない。結果が画面に出ないときは、画面の上部の中央にトーストを出す。

| 結果が画面に出る（トーストを出さない） | 結果が画面に出ない（トーストを出す） |
|---|---|
| 一覧に登録した行が増える、完了の表示が出る、取り消した行に「取り消し済み」のバッジが付く、次の画面に移る | 保存したが、画面はボタンが処理中から戻るか、押せない状態に戻るだけ |

ボタンが処理中から戻ることや、押せない状態に戻ることは、処理が終わったことを示すだけで、成功したかどうかは示さない。そのため、結果が画面に出たことには数えない。

- トーストは success のアラートと同じ色で表示し、閉じるボタンを付ける
- 5 秒で消える。ポインターを重ねているあいだは消えない
- 出たときにスクリーンリーダーで読み上げる。フォーカスは移さない
- 続けて出たときは重ねて表示し、ポインターを重ねると広げて全部を見せる

## 確認

元に戻せない操作（削除、取り消し、破棄など）の前に、本当に実行してよいかを、確認のダイアログ（`ui/src/components/confirm-dialog.tsx`）で確かめる。ブラウザの `confirm()` は使わない。

| 部分 | 書くこと |
|---|---|
| 見出し | 「{対象}の{操作}」 |
| 本文 | 「以下の{対象}を{操作}しますか？　この操作は元に戻せません。」 |
| 対象 | 人が見て分かる項目（名前、日時、金額など）。ID は使わない |
| 注意事項 | 操作で失われるものなど。あれば警告のアラートで書く |
| ボタン | 左に「やめる」、右に実際に起きること（「削除」「取り消す」「破棄する」）。「OK」「はい」は使わない。確定のボタンは destructive にする |

- 開いたら、最初のフォーカスを「やめる」に置く
- 確定のボタンを押してから処理が終わるまで、確定のボタンを処理中にする。失敗したら、ダイアログを開いたまま、下部のボタンのすぐ下に失敗のアラートを浮かせて出す（「処理の失敗」の「浮かせて重ねるとき」）

### 強い確認

まとまった記録が失われる操作では、操作の名前をテキスト欄に入力するまで、確定のボタンを押せないようにする。入力させる言葉は見出しの「{操作}」と同じにする（セッションの破棄なら「破棄」）。入力欄の名前は「確認のため「{言葉}」と入力してください」とする。ダイアログを閉じたら、入力を空に戻す。

## フレーム

フレーム（`ui/src/frame/sidebar-frame.tsx` の `Frame`）は、すべての画面の外側に置き、画面を切り替えるメニューと、本文の上端の帯を表示する。どの項目を並べるか、いつ開閉するかは [../ナビゲーション.md](../ナビゲーション.md) にある。

### 構成

| 部分 | 内容 |
|---|---|
| 上端のバー | 左から、メニューを開閉するボタン、アプリのアイコン、アプリの名前。画面の幅いっぱいに、常に表示する |
| メニュー | 上端のバーの下の左側の列。画面の項目をグループに分けて並べる。項目が 1 つのグループは見出しを出さない |
| 帯 | 本文の上端の細い帯。選んでいる画面のプライマリカラーにする。メニューの上には出さない |
| 本文 | 帯の下 |

### 開閉

- 画面の幅が 768px 以上なら、メニューは本文を右へ押し出して表示する
- 768px 未満なら、メニューは本文の上に重ねて表示し、上端のバーより下の本文を、ダイアログと同じ覆い（`--overlay`）で隠す
- 閉じているときは、メニューも覆いも表示しない。帯は開閉によらず表示する

### 色

| 部分 | 色 |
|---|---|
| 上端のバーとメニューの背景 | gray-900 |
| 上端のバーの文字 | 白 |
| メニューの項目の文字 | gray-300 |
| グループの見出し | gray-400 |
| 選んでいる項目 | 角丸の背景を、その画面のプライマリカラーで塗る。文字は `--primary-foreground` の太字 |
| ポインターを重ねた項目 | 角丸の背景に、その項目の画面のプライマリカラーを 25% の不透明度で重ねる。文字は白 |
| フォーカスリング | 白（`#ffffff`）の 2px。メニューの項目では、項目の縁に付けて外側に出す（離さない）。メニューを開閉するボタンでは、外側に 2px 離して出す |
| 帯 | 選んでいる画面のプライマリカラー |

フォーカスリングはメニューの背景（gray-900）の上に出るので、ほかの部品の `--ring` ではなく白にする。

### 寸法

- 上端のバーの高さは 56px。アイコンは 36px 四方
- メニューの幅は 224px。メニューの内側の余白は上下 4px、左右 8px で、項目はその内側に並べる
- 項目は角丸（6px）。項目の内側の余白は上下 12px、左右 16px
- 項目どうしの間は 8px 空ける。1 項目のグループが続く所（「即売会」と「商品管理」など）も同じにする。グループの見出しと、その下の項目の間は 4px にする
- 帯の高さは 4px

### 文字

| 部分 | テキストスタイル |
|---|---|
| アプリの名前 | 見出し（中）（18px の太字） |
| メニューの項目 | 本文（14px の標準） |
| 選んでいる項目 | 本文を太字にしたもの（14px の太字） |
| グループの見出し | 補足（12px の標準） |

### アクセシビリティ

- メニューを開閉するボタンの名前は、開いているときは「メニューを閉じる」、閉じているときは「メニューを開く」にし、`aria-expanded` で開いているかを示す
- 選んでいる項目に `aria-current="page"` を付ける
