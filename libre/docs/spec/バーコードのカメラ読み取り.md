# バーコードのカメラ読み取り

端末のカメラで商品のバーコードを読み、バーコードリーダーで読んだときと同じように商品を入力する。バーコードリーダーを出さずに、スマートフォンやタブレットで作業するために使う。

## 対象の画面

商品のバーコードを入力する欄の横に「カメラ」ボタンを置く。入力欄が見えているときだけ表示する。入力欄を商品の一覧のプルダウン（切り替えのボタンの名前は「一覧から選択」）に切り替えられる画面では、プルダウンに切り替えているあいだは表示しない。

| 画面 | 入力欄 | 実装 | 欄の種類 |
|---|---|---|---|
| 即売会の前日準備 | 商品を足す欄 | `src/common/item/item-input.tsx`（`ItemInput`） | 確定する欄 |
| 即売会の商品・価格編集 | 商品を足す欄 | `ItemInput` | 確定する欄 |
| 即売会のレジ | 商品の欄。「バーコード」と「手打ち」のどちらのときも表示する | `src/pages/event/register/register.tsx` | 確定する欄 |
| 商品マスタの「ISDNから商品を追加」のカード | ISDN の欄 | `src/pages/items/add-by-isdn.tsx`（`AddByISDN`） | 確定する欄 |
| 即売会の商品・価格編集の「新規商品を登録」 | 「ISDNでスキャン」のときの ISDN の欄 | `AddByISDN` | 確定する欄 |

- 確定する欄: Enter キーか、横のボタン（「追加」「選択」）で、入力した値を確定する欄

ISDN の欄では、読んだ商品 ID を ISDN として扱い、入力欄に 13 桁を打ち込んだときと同じように、入力欄に入れて、Enter キーやボタンを待たずに追加する（[商品マスタ.md](商品マスタ.md) の「ISDN から登録する」）。追加できたら入力欄を空にし、追加できなければ入力欄に残す。ISDN は先頭が 278 か 279 の商品 ID である（[index.md](index.md) の「概念モデル」の「商品」）。インストアコード（先頭が 271）を読んだときも、打ち込んだときと同じく画面では確かめずに取得し、取得の失敗として扱う。

## 入力

- 端末のカメラの映像。背面のカメラを優先し、背面のカメラがなければほかのカメラを使う（`getUserMedia` の `facingMode: { ideal: "environment" }`）

## 出力

- 読んだ商品 ID（13 桁の数字の文字列）
  - 入力欄に打ち込んで確定したときと同じ処理に渡す。商品が見つからない、すでに追加してある、などの表示も打ち込んだときと同じにする

## 要件

### 読み取りの流れ

1. 「カメラ」ボタンを押したら、ダイアログを開き、カメラの映像を表示して読み取りを始める
2. EAN-13 のバーコードだけを読む
3. 読んだ値が商品 ID の形式に合わなければ、無視して読み続ける。形式の判定には `shared/entity/items/item_id.ts` の `validateItemID` を使う。商品 ID の横に印刷された、ほかのバーコード（価格を表す 2 段目のバーコードなど）を読んでも、入力しないようにするため
4. 映像の上下の真ん中に引いた横の線（下の「映像と線の表示」）にかからないバーコードは、無視して読み続ける。線にかかるとは、`detect` が返す `boundingBox` の上端が線の位置以下で、下端が線の位置以上であることをいう。線の位置は映像のフレームの高さの半分とする。映像のフレームの大きさは映像そのものの画素の大きさ（`video.videoWidth` と `video.videoHeight`）を指し、`boundingBox` も同じ座標で比べる。画角に入った、狙っていないバーコードを読まないようにするため
5. 2〜4 を満たす値が 1 つのフレームに 2 つ以上あれば、`boundingBox` の横の中心が映像のフレームの横の中心に最も近いものを選ぶ。距離が同じなら、`detect` が返した順で先のものを選ぶ
6. 値を選んだら、読み取れたことをフィードバックする（下の「読み取り時のフィードバック」）。フィードバックのあいだは次のフレームを読まない。フィードバックが終わったら、カメラを止めてダイアログを閉じ、閉じたあとで値を出力に渡す。フィードバックのあいだに「閉じる」ボタンか Esc キーで閉じたときは、値を渡さない
7. ダイアログの「閉じる」ボタンを押すか、Esc キーを押したら、何も渡さずにカメラを止めて閉じる。ダイアログの外を押しても閉じない

- ダイアログを閉じたら、どの閉じ方でも、カメラを止める（取得した映像のトラックをすべて `stop` する）
- 映像のフレームごと（`requestAnimationFrame` のたび）に読む。ただし、前のフレームの読み取りが終わるまでは次のフレームを読まず、読み取りを重ねて走らせない
- 即売会の画面（前日準備、レジ、商品・価格編集）では、ダイアログを上端に揃えて表示する（[即売会/index.md](即売会/index.md) の「当日の画面に共通する要件」）
- レジではダイアログを閉じたあと、入力欄にフォーカスを戻す

### 映像と線の表示

- 映像の枠は横 4、縦 3 の比にし、映像が届く前から同じ大きさで表示する。映像が届いたときに枠の大きさが変わらないようにするため。映像の縦横比が枠と違うときは、映像の中心を合わせ、枠からはみ出す部分を切って表示する（`object-fit: cover`）
- 枠の上下の真ん中に、横の線を枠の幅いっぱいに引く。利用者は読みたいバーコードにこの線を合わせる。枠は映像の中心を合わせて切るので、表示した線の位置は映像のフレームの上下の真ん中と一致する
- 読み取るまでは、線を赤の細い破線（太さ 2 px）にする。読み取れたら、緑の太い実線（太さ 4 px）にし、線のすぐ上（線に重ねない）の横の真ん中に、チェックの印と「読み取りました」の文字を出す。印と文字は、緑（下の `#03AF7A`）の背景に、濃い灰色（`#111827`）で書く。文字のコントラスト比を 4.5 以上にするため（白い背景に緑の文字では 2.83 になる）。色が見分けられなくても、線の形と文字で読み取れたことが分かるようにするため
- 赤と緑は、カラーユニバーサルデザイン推奨配色セット ver.4.2 の画面用の色にする。赤は `#FF4B00`（RGB 255, 75, 0）、緑は `#03AF7A`（RGB 3, 175, 122）

### 読み取り時のフィードバック

- バーコードを読み取れたら、どの端末でも、線を読み取れたときの表示（上の「映像と線の表示」）に変え、変えた時点から 0.7 秒そのまま表示してから閉じる。「読み取りました」の文字を読める長さにするため
- 表示を変えるのと同時に、ブラウザが `navigator.vibrate` を持てば（Android の Chrome など）、100 ミリ秒振動させる。持たないブラウザ（iPad や iPhone の Safari など）では振動しない

### 「カメラ」ボタンの表示

- ボタンの文字は改行しない（`white-space: nowrap`）。横幅が足りないときは、ボタンを縮めず、隣の入力欄を縮める

### カメラを使えないとき

ダイアログに、理由を 1 文で表示する。映像は表示しない。

| 状況 | 表示 |
|---|---|
| ブラウザが `navigator.mediaDevices.getUserMedia` を持たない（HTTPS でないページなど） | このブラウザではカメラを使えません |
| カメラの使用を許可されなかった（`NotAllowedError`） | カメラの使用が許可されていません |
| カメラが見つからない（`NotFoundError`） | カメラが見つかりません |
| それ以外で起動に失敗した | カメラを起動できませんでした |
| カメラは起動したが、読み取りを始められない（`BarcodeDetector` を作れない、`detect` が失敗した、`.wasm` を読み込めないなど） | バーコードを読み取れません |

### 読み取りの実装

- ブラウザ標準の `BarcodeDetector` を使う。ブラウザが持たないときは、`barcode-detector` の ponyfill（`barcode-detector/ponyfill`）の `BarcodeDetector` を使う。`barcode-detector/polyfill` は import するだけで `globalThis.BarcodeDetector` に実装を入れ、ブラウザが標準を持つかを判別できなくなるので使わない
- ブラウザが標準を持つかは、`globalThis.BarcodeDetector` があるかで判定する
- ponyfill が使う `.wasm`（`zxing-wasm/reader/zxing_reader.wasm`）は、アプリのビルドに含めて配る。CDN から取得しない。即売会の会場はオフラインのため。`.wasm` は Vite の `?url` で import してビルドに含め、その URL を `barcode-detector/ponyfill` の `prepareZXingModule` に `overrides.locateFile` で渡す。`fireImmediately` を付けずに呼ぶと、`.wasm` を読み込まずに場所だけを設定する
- ブラウザが `BarcodeDetector` を持たないときは、アプリを開いたとき（どの画面から開いたかによらず、アプリの起動時。`src/main.tsx` から呼ぶ）に `.wasm` を読み込んでおく（`prepareZXingModule` の `fireImmediately: true`）。オンラインのうちに読み込んでおけば、オフラインになってもカメラで読めるようにするため

## 確かめ方

- 読んだ値を入力するか無視するか、2 つ以上あるときにどれを選ぶかの判定は、単体テストで確かめる。`boundingBox` と映像のフレームの大きさを入力に与える
- ボタンでダイアログが開き、映像を表示し、「閉じる」でカメラが止まることは、代表として即売会の前日準備の画面で、e2e テストで確かめる。Chromium の偽のカメラ（`--use-fake-device-for-media-stream` と `--use-fake-ui-for-media-stream`）を使う
- ISDN の欄（`AddByISDN`）に「カメラ」ボタンを表示し、文字が改行せず、ボタンでダイアログが開き「閉じる」で閉じることは、商品マスタの画面で、e2e テストで確かめる
- 実際のバーコードを読めることは、iPad の Safari と Android の Chrome の実機で、手で確かめる
