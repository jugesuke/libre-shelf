# 即売会

同人誌即売会に参加する 1 日を、前日の準備から帰着後の振り返りまで、1 つの流れで記録する。当日は販売を手早く記録し、帰着後に在庫とレジ金を突き合わせて差を調べ、直す。

## 前提

- 端末はどの状態でも iPad を使う。データは iPad の localStorage にあるので、前日の準備も帰着後の作業も iPad で行う
- 当日の会場はオフラインを前提にする。サーバの API を使うのは、商品マスタに ISDN から商品を登録するとき（[../商品マスタ.md](../商品マスタ.md)）だけで、即売会の画面はオフラインで使える
- 支払いは現金だけを扱う
- 進行中のセッションは localStorage に 1 イベント 1 件の JSON として持つ。帰着後の作業を終えたら、端末のセッションの履歴に保存する（[セッションの保存.md](セッションの保存.md)）
- 商品名とサークル名は、おしながきに足したときに商品マスタ（[../商品マスタ.md](../商品マスタ.md)）から写した値（[セッションのデータ.md](セッションのデータ.md) の `MenuEntry`）を表示する。商品マスタの商品を直したり消したりしても、セッションの表示は変わらない。商品マスタが読めないときは、商品を足す画面（前日準備と、レジの商品・価格編集）でだけアラートを出す

## 状態

即売会の 1 日を、次の 5 つの状態で表す。状態は前にだけ進む。例外として、当日終了処理からレジへ戻れる。

```
前日準備 → 当日開始処理 → レジ → 当日終了処理 → イベント終了
```

| 状態 | `phase` | 場所 | 操作する人 | 内容 | 仕様 |
|---|---|---|---|---|---|
| 前日準備 | `preparation` | 自宅など | サークル主 | おしながき（商品と価格）を登録する | [前日準備.md](前日準備.md) |
| 当日開始処理 | `opening` | 会場 | サークル主 | レジ金、見本誌、持ち込んだ在庫を確かめる | [当日開始処理.md](当日開始処理.md) |
| レジ | `register` | 会場 | サークル主、売り子 | 販売と来場者を記録する | [レジ.md](レジ.md)、[集計画面.md](集計画面.md) |
| 当日終了処理 | `closing` | 会場 | サークル主 | 在庫とレジ金を確かめる | [当日終了処理.md](当日終了処理.md) |
| イベント終了 | `done` | 帰着後の自宅 | サークル主 | 差を調べて直し、履歴に保存する | [イベント終了.md](イベント終了.md) |

セッションのデータ構造は [セッションのデータ.md](セッションのデータ.md)、履歴に保存したセッションの一覧と、それを見る画面は [セッションの保存.md](セッションの保存.md) と [結果画面.md](結果画面.md)、お釣りの金種が足りたかを終了後に振り返る計算は [お釣りの振り返り.md](お釣りの振り返り.md) に書く。

## セッションの再開と破棄

- アプリを開いたとき、`settled=false` のセッションがあれば、上書きせずにそのまま再開する。`phase` に対応する画面を表示し、`preparation` ならおしながきの登録画面を、登録した内容を残したまま表示する
- どの状態のどの画面にも「セッションを破棄する」ボタンを置く。目立たない場所に小さく表示する
- 破棄のボタンを押したら、確認の「強い確認」（[../デザイン/index.md](../デザイン/index.md) の「確認」）で、テキスト欄に「破棄」と入力させて確かめる。見出しは「セッションの破棄」、本文は「このセッションを破棄しますか？　この操作は元に戻せません。」、注意事項は「この即売会の会計とレジ金の記録が、すべて失われます。」、確定のボタンは「破棄する」。入力は「破棄」と完全に一致したときだけ確定のボタンを押せる。確かめたら localStorage からセッションを消し、前日準備（新しいセッションの作成）に戻る

## 持ち込み数の基準

当日開始処理では、数えた持ち込み数を、前日準備で入力した数（持ち込み数の基準）と比べて差を表示する（[当日開始処理.md](当日開始処理.md)）。基準は商品の種類で分ける。

| 商品 | 基準 | 記録する場所 |
|---|---|---|
| 自サークルの頒布物 | 持ち込む予定の数（持ち込み予定数） | セッションの `plannedStock` |
| 委託物 | 受け取ったときに数えた数（預かり部数） | セッションの `consignedStock` |

## 委託物

他のサークルから預かった委託物は、イベントごとに、持ち込んだ数、出た数（販売、見本誌の提出、展示見本）、残り（返す数）が分かればよい。

- 委託物かどうかは、おしながきの委託元名（`MenuEntry.consignorName`）があるかで決める。空白だけの入力は、委託元名がないものとして扱う
- 委託物の預かり部数は、おしながきの登録で必ず入力する
- 見本誌の提出と展示見本は、委託物も自サークルの頒布物と同じように入力する

## 当日の画面に共通する要件

| 要件 | 内容 |
|---|---|
| タッチで操作する | iPad で操作する |
| スクロールさせない | 情報が多いときは、ページを切り替える |
| 要らない要素を置かない | 接客の妨げになる要素を置かない |
| ダイアログは上に寄せる | 中央に置かず、上端に揃えて表示する |
| テンキーは画面に独自に作る | ソフトウェアキーボードを使わない |
| バーコードリーダーと IME の干渉 | 日本語入力が有効だと、バーコードを正しく読めないことがある。実機で確かめて対処する。参考: [IMEとinputとキーボードショートカットの話](https://ef81sp.github.io/ime-vs-input-keyboard-shortcut/1) |

## まだ決まっていないこと

- PC から操作できるようにするか
- キャッシュレスの支払いへの対応と、現金とキャッシュレスの比率の分析
- 商品を画面の一覧から選んでレジに入れる操作（今はバーコードの読み取りだけ）
- バーコードリーダーと IME の干渉への対策
- 過去の複数のイベントを比べる画面（総売上、商品ごとの売上、来場者数）
