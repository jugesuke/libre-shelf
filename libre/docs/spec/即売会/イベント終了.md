# イベント終了

帰着後に、在庫とレジ金を突き合わせて差を直し、セッションを端末の履歴に保存する。直しては確かめることを繰り返すので、1 つの画面で行う。

## 在庫の確定

画面のタブは「在庫」「レジ金」「委託」の 3 つである。在庫のタブの先頭に「在庫の確定」の区画を置く。

1. 在庫に差があれば、原因を調べる（数え間違い、見本誌の数の入れ忘れなど）
2. 画面の入力欄で、残った在庫の数、持ち込んだ在庫の数、見本誌の提出数、展示見本の数を直す。画面は入力した値で理論在庫と差を計算し直して表示する
3. 差がなくなったら、「在庫を確定する」ボタンを押す。在庫のタブの入力欄の値と一緒に、セッションの `stockDifference` を空の配列にして保存する。差が残っているあいだは、このボタンを押せない

理論在庫と差の計算は、当日終了処理と同じである（[当日終了処理.md](当日終了処理.md) の「手順 1」と「手順 3」）。差は、保存した値ではなく入力欄の値で計算する。確定したあとは、在庫のタブの入力欄を直せなくし（値は表に表示したまま）、在庫のタブの各表の見出しの右に「在庫を確定済みのため変更不可」と表示し、「在庫情報を保存」ボタンも置かない

区画の表示は次のとおり。

| 状態 | 表示 |
|---|---|
| 確定が済んでいる（`stockDifference` が空の配列） | 「在庫を確定しました。」。ボタンは置かない |
| 確定が済んでおらず、差がない | 「在庫差異はありません。在庫を確定できます。」と、押せるボタン |
| 確定が済んでおらず、差がある | 「在庫差異があります」と、商品ごとの差（「商品名：+1 部」の形）、「差異の原因を調査し、下の入力値を修正してから再確認してください。」と、押せないボタン |

## 直せる項目

- 残った在庫の数（商品ごと）
- 持ち込んだ在庫の数（商品ごと）
- 開始時のレジ金（[当日開始処理.md](当日開始処理.md) の「レジ金の入力」で、金種ごとに直す）
- 見本誌の提出数
- 展示見本の数
- 終了時のレジ金（開始時のレジ金と同じ入力欄で、金種ごとに直す）
- レジ金の出し入れの記録（行の追加、編集、削除。入れた枚数と出した枚数を金種ごとに直す。入力欄は [レジ.md](レジ.md) の「レジ金の出し入れ」と同じ。編集しても、記録の日時は変えない。日時はお釣りの振り返りの計算で出来事の順序に使う）
- 委託元名（商品ごと。下の委託タブで直す）。「委託元を保存」で保存するとき、委託元名は前後の空白を除いて記録し、空になったら委託元名を消したものとする。委託物でなくなった商品の預かり部数（`consignedStock`）は消す。新しく委託物にした商品の預かり部数は記録しない。委託タブの入荷には、持ち込んだ在庫の数を使う

残った在庫の数、持ち込んだ在庫の数、見本誌の提出数、展示見本の数は、1 以上の整数だけを記録し、それ以外の値は入力していないものとして扱う。差の計算では 0 とみなす。「在庫情報を保存」では `stockDifference` を変えない。`stockDifference` を空の配列にするのは「在庫を確定する」だけである

## 委託タブ

- おしながきで入力した委託元名を表示し、直せるようにする。直すのはおしながきの `consignorName` である
- 委託元ごとに、商品ごとの「入荷（持ち込み）、販売、見本誌提出、展示見本、残部（返却数）、売上金額」と、委託元ごとの売上の合計を表示する
- 売上金額はトランザクションに記録した販売時の価格で集計する
- 残った在庫の数（`closingStock`）を入力していない商品の残部は、「—」と表示する
- 委託元ごとのカードに「コピー」ボタンを置き、報告用のテキストをクリップボードにコピーできるようにする

コピーするテキストは次の Markdown のリストの形にする。表ではなくリストにする。数値は画面の表と同じ集計値を使う。

```markdown
## 委託販売報告（2026-07-10）: ○○サークル さま

- 商品A: 入荷 10 / 販売 6 / 見本誌提出 1 / 展示見本 1 / 返却 2 / 売上 ¥3,000

売上合計: ¥3,000
```

同じ表示とコピーの機能を、結果画面（[結果画面.md](結果画面.md)）にも置く。

## 履歴への保存

1. 直し終えたら、「履歴に保存」ボタンを押す
2. localStorage に保存したセッションを、セッションの履歴に足す（[セッションの保存.md](セッションの保存.md)）
3. 足せたら、進行中のセッションに `settled = true` を記録し、即売会の一覧（`/event`）へ移る
4. 足せなかったら（localStorage の容量が足りないなど）、「履歴に保存できませんでした。端末の空き容量を確認して、もう一度保存してください。」と、ボタンの行の、「ファイルに書き出す」の左に destructive のアラートで表示する（[../デザイン/index.md](../デザイン/index.md) の「処理の失敗」）。進行中のセッションは残す
5. 履歴に保存したセッションは、次のイベントの前日準備を始めるときに、進行中のセッションとしては消す。履歴には残る

### 保存できる条件

- 在庫の確定が済むまで、「履歴に保存」ボタンは押せない。確定が済んだかは、セッションの `stockDifference` が空の配列かで判定する。`null` か、1 件以上の差を持つなら済んでいない。`stockDifference` には、差が 0 でない商品だけを入れる
- 確定が済んでいないあいだは、ボタンの横に「在庫を確定してから保存してください」と表示する
- 保存していない入力があるあいだも、ボタンは押せない。履歴に足すのは localStorage に保存したセッションで、画面の入力欄の値は足さないため。保存していない入力とは、上の「直せる項目」のどれかについて、入力欄の値が保存したセッションの値と違うことをいう。項目は、次の 3 つのボタンで分けて保存する
  - 「在庫情報を保存」: 残った在庫の数、持ち込んだ在庫の数、見本誌の提出数、展示見本の数
  - 「レジ金を保存」: 開始時のレジ金、終了時のレジ金、レジ金の出し入れの記録
  - 「委託元を保存」: 委託元名
- 確定が済んでいて、保存していない入力があるときは、ボタンの横に「保存していない入力があります」と表示する。確定が済んでいないときは、確定の文言だけを表示する。どちらでもないときは、文言を表示しない

「履歴に保存」のボタンは、在庫の確定が済んだら primary、済むまでは secondary にする。在庫の確定が済むまでは「在庫を確定する」が primary なので、同じ画面に primary が 2 つ並ばないようにするため（[../デザイン/index.md](../デザイン/index.md) の「ボタン」）。

## ファイルへの書き出し

「履歴に保存」ボタンの隣に「ファイルに書き出す」ボタンを置く。押したら、localStorage に保存したセッションをファイルとしてダウンロードさせる（形とファイル名は [セッションの保存.md](セッションの保存.md) の「ファイルへの書き出し」）。在庫の確定が済んでいなくても押せる。保存していない入力があるあいだは押せない。
