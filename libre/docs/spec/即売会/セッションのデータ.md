# セッションのデータ

即売会 1 日分のデータ（セッション）を、localStorage に JSON で持つ。帰着後の作業を終えたら、同じ JSON をセッションの履歴に保存する（[セッションの保存.md](セッションの保存.md)）。

## localStorage

- キーは `event_session` に固定する
- 1 台の端末にはセッションを 1 件だけ持つ
- `settled = true`（履歴に保存した）セッションは、次の前日準備で新しいセッションを作るときに消して上書きする
- 今のスキーマで `settled = false` のセッションがあれば、アプリを開いたときに必ずそのセッションを再開する。新しいセッションを作るには、先にそのセッションを破棄する（[index.md](index.md) の「セッションの再開と破棄」）
- `schemaVersion` が今のスキーマと違うセッションは読み込まず、セッションがないものとして扱う。古いスキーマのセッションを今のスキーマに変換する処理は作らない。スキーマは、`settled = false` のセッションが localStorage にないとき（イベントの合間）に変える

## スキーマのバージョン

各セッションに `schemaVersion` を持たせる。値はスキーマを変えた日付（`YYYY-MM-DD`）である。今のスキーマは `2026-11-21` だけで、ほかのバージョンは扱わない。

型は `shared/entity/event/v2026-11-21/` に置く。下の型の `EventSession` は、Libre Shelf のセッション（`libre-event-session.ts` の型）である。`event-session.ts` は、このスキーマの共通の項目の型で、`libre-event-session.ts` は、Libre Shelf のセッション（`eventName` と `plannedStock` を足したもの）の型である。

## 今のスキーマ `2026-11-21`

```typescript
// フェーズ
type EventSessionPhase =
  | "preparation"  // 前日準備
  | "opening"      // 当日開始処理
  | "register"     // レジ
  | "closing"      // 当日終了処理
  | "done";        // イベント終了

type ItemQuantity = {
  itemId: string;
  quantity: number;
};

// 見本誌の提出と展示見本に使う
type ItemQuantityWithTime = {
  itemId: string;
  quantity: number;
  occurredAt: string; // 入力した時刻（下の「時刻の書き方」）
};

type ItemDifference = {
  itemId: string;
  difference: number;
};

type MenuEntry = {
  itemId: string;
  productName: string;   // 商品名。おしながきに足したときに、商品マスタから写す
  publisherName: string; // サークル（発行者名）。同じく写す
  price: number; // このイベントでの頒布価格
  consignorName?: string; // 委託元名。あれば委託物、なければ自サークルの頒布物
};

// 金種ごとの枚数。6 つのキーをすべて持ち、0 以上の整数を入れる
// 1、5、10、50 円は金種ごとには扱わない
type DenominationCounts = {
  "100yen": number;
  "500yen": number;
  "1000yen": number;
  "2000yen": number;
  "5000yen": number;
  "10000yen": number;
};

// 数えたレジ金
type CashCount = {
  counts: DenominationCounts;
  other: number; // 1、5、10、50 円の硬貨の合計の金額。0 以上の整数
};

type CashAdjustment = {
  occurredAt: string; // 記録した時刻（下の「時刻の書き方」）
  cashIn: DenominationCounts;  // レジに入れた枚数
  cashOut: DenominationCounts; // レジから出した枚数
  comment: string;
};

type Transaction = {
  transactionId: string; // UUID
  occurredAt: string; // 会計を確定した時刻（下の「時刻の書き方」）
  buyerType: "acquaintance" | "stranger";
  items: TransactionItem[];
  tendered: DenominationCounts; // 預かった硬貨と紙幣の枚数。レジの積み上げのボタンを押した回数
  changeAmount: number;         // お釣りの金額
  cancelled: boolean;
};

type TransactionItem = {
  itemId: string;
  productName: string; // 販売したときの商品名。会計を確定したときに、おしながきから写す
  price: number; // 販売したときの価格
  quantity: number;
};

type VisitorLog = {
  occurredAt: string; // 記録した時刻（下の「時刻の書き方」）
};

type EventSession = {
  schemaVersion: string; // YYYY-MM-DD
  eventName: string; // 即売会の名前。前日準備で入力する
  eventDate: string; // YYYY-MM-DD（開始日）。前日準備の初期値は、端末のタイムゾーンでの今日

  phase: EventSessionPhase;

  // おしながき。前日準備で登録し、レジで編集できる
  menu: MenuEntry[];

  // 当日開始処理で入力する
  openingCash: CashCount | null; // 開始時のレジ金
  cashAdjustments: CashAdjustment[];

  // 持ち込んだ在庫の実際の数。開催中に追加で受け取った分を手で直したものも含む
  openingStock: ItemQuantity[];

  // 自サークルの頒布物（menu の consignorName がない商品）の持ち込み予定数。前日準備と、レジの商品・価格編集で入力する
  plannedStock: ItemQuantity[];

  // 委託物（menu の consignorName がある商品）の預かり部数。前日準備と、レジの商品・価格編集で入力する
  consignedStock: ItemQuantity[];

  // 見本誌の提出と展示見本
  sampleSubmissions: ItemQuantityWithTime[];
  displaySamples: ItemQuantityWithTime[];

  transactions: Transaction[];

  visitorLogs: VisitorLog[];

  // 当日終了処理で入力する
  closingStock: ItemQuantity[] | null;
  closingCash: CashCount | null;

  cashDifference: number | null; // 合計の金額の差

  stockDifference: ItemDifference[] | null; // 在庫の差（残った在庫の数 − 理論在庫）。null は当日終了処理の前。空の配列なら在庫を確定した（イベント終了.md）
  settled: boolean; // 履歴に保存したか
};
```

- 時刻の書き方: セッションの中の時刻は、どれも端末のタイムゾーンの時差を付けた ISO 8601 の文字列で、書いたときの端末のタイムゾーンの時差を付けて、秒まで書き、秒の小数は切り捨てる（例: `2026-12-30T10:30:00+09:00`）。セッションを読み込むときは、`Z` で終わる時刻と、秒の小数がある時刻も受け付け、書き直さずにそのまま持つ。並べるときは、文字列ではなく時刻として比べる
- 会計の明細の `productName` は、会計を確定したときにおしながきから写す。そのあと、おしながきから商品を外しても、会計の商品名は残る。会計の商品名は、この値から出す。写すときにおしながきにその商品がなければ、商品 ID を入れる
- おしながきの `productName` と `publisherName` は、前日準備と、レジの商品・価格編集で商品を足したときに、商品マスタから写す。そのあと商品マスタの商品を直したり消したりしても、セッションの値は変えない。即売会の画面、結果画面、書き出したファイルは、商品名とサークル名をこの値から出す
- レジの集計と結果画面で商品ごとに名前を出すときは、おしながきの `productName` を使い、おしながきにない商品は会計の明細の `productName` を使う。会計の明細は、取り消した会計も含めて `transactions` の並びの順に探し、最初に見つかった名前を使う。どちらにもなければ商品 ID を出す
- レジ金の合計の金額は `counts` の金種ごとの金額（金種 × 枚数）の合計に `other` を足したものである
- 預かった金額は `tendered` の金種ごとの金額の合計である。`changeAmount` は預かった金額 − 販売の合計である
- レジ金の出し入れの金額は `cashIn` の金額の合計 − `cashOut` の金額の合計である。両替なら、両方に枚数が入る
- 1、5、10、50 円の硬貨は、会計とレジ金の出し入れでは記録しない
