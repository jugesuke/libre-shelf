# セッションの保存

帰着後の作業を終えたセッションを、端末の localStorage にセッションの履歴として保存する。保存したセッションは即売会の一覧と結果画面（[結果画面.md](結果画面.md)）で見る。サーバには送らない。

## セッションの履歴

localStorage のキー `event_session_history` に、次の形の配列を JSON で持つ。進行中のセッション（キー `event_session`、[セッションのデータ.md](セッションのデータ.md)）とは別に持つ。

```typescript
type EventSessionRecord = {
  id: string;      // 保存したときに作る UUID。結果画面のパスに使う
  savedAt: string; // 保存した時刻。書き方はセッションのデータ.md の「時刻の書き方」
  session: EventSession; // 保存したときのセッション。スキーマは「セッションのデータ.md」の今のスキーマ
};
```

- 履歴に足すのは、イベント終了の画面の「履歴に保存」ボタン（[イベント終了.md](イベント終了.md)）と、データの管理の画面での読み込み（下の「ファイルからの読み込み」と [../データの管理.md](../データの管理.md)）の 2 つである
- 足すときは、localStorage に保存した進行中のセッションを、そのまま `session` に入れる。足したあとの進行中のセッションの変更は、履歴に反映しない
- 同じイベント、同じ日のセッションを、複数保存してよい（昼に一度締めて再開する場合など）
- 書き込みに失敗したら（localStorage の容量が足りないなど）、履歴を変えずに、呼び出した画面に失敗を知らせる。画面での表示は [イベント終了.md](イベント終了.md) の「履歴への保存」に書く
- localStorage の値が読めない（JSON として壊れている、配列でない）ときは、履歴が 0 件のものとして一覧を表示し、値は書き換えない。そのあいだは履歴に足せず、「履歴に保存」は失敗として扱う
- 配列の中に読めない要素があれば、その要素だけを一覧から除いて表示する。履歴に足すときも、読めない要素は消さずに残す。結果画面で読めない要素の `id` を開いたときは、履歴にないものとして扱う。読めない要素とは、`id`、`savedAt`、`session.eventName`、`session.eventDate`、`session.schemaVersion` のどれかが文字列でない要素をいう。`session` のほかの項目は一覧では確かめない（結果画面で `schemaVersion` を確かめる）

## 即売会の一覧

パスは `/event` で、メニューの「即売会」から開く。

- 進行中のセッション（`settled = false`、[セッションのデータ.md](セッションのデータ.md)）があれば、一覧を表示せず、`/event/session` へ移る（[index.md](index.md) の「セッションの再開と破棄」）
- 右上に「新しい店を開始する」ボタンを置き、押したら `/event/session`（前日準備）へ移る。「店」は、即売会で出すサークルの売り場を指す
- 表には履歴の 1 件ごとに、即売会（`session.eventName`）と開催日（`session.eventDate`）の列を置く。開催日（`YYYY-MM-DD` の文字列）の新しい順に並べ、開催日が同じなら保存した日時の新しい順にする
- 行を押すか、行にフォーカスして Enter キーを押したら、結果画面（`/event/result/{id}`）へ移る
- 履歴がなければ「過去のイベント記録がありません。イベント終了の画面で「履歴に保存」を押すと、ここに表示されます。」と表示する

## 履歴から消す

試しに作った記録や、まちがえて保存した記録を、履歴から 1 件ずつ消せるようにする。

- 結果画面の見出しの右に、destructive の「削除」ボタンを置く（[結果画面.md](結果画面.md)）
- 押したら、確認の「強い確認」（[../デザイン/index.md](../デザイン/index.md) の「確認」）で、テキスト欄に「削除」と入力させて確かめる。見出しは「記録の削除」、本文は「以下の記録を削除しますか？　この操作は元に戻せません。」、対象は「即売会」（即売会の名前）と「開催日」（`YYYY/MM/DD`）、注意事項は「この即売会の会計とレジ金の記録が、すべて失われます。残したいときは、先に「ファイルに書き出す」で保存してください。」、確定のボタンは「削除」とする
- 確かめたら、履歴からその 1 件を消し、即売会の一覧（`/event`）へ移る。確認のあいだに、別のタブなどで同じ記録がすでに消えていたときも、消せたものとして一覧へ移る
- 消すのに失敗したら（localStorage に書き込めないなど）、確認のダイアログを開いたまま、「記録を削除できませんでした。端末の空き容量を確認して、もう一度削除してください。」と表示する（[../デザイン/index.md](../デザイン/index.md) の「確認」）

## ファイルへの書き出し

ほかの道具で分析したり、端末のデータが消えても残したりできるように、セッションを 1 件ずつファイルに書き出す。書き出したファイルは、1 件だけで意味が分かり、ほかの道具に渡しても読み違えないようにする。

- ファイルの中身は、次の形の JSON にする

```typescript
type SessionFile = {
  format: "libre-shelf-session"; // ファイルの種類
  version: 1;                     // このファイルの形のバージョン
  exportedAt: string;             // 書き出した時刻（セッションのデータ.md の「時刻の書き方」）
  session: EventSession;          // セッション（セッションのデータ.md）。商品名とサークル名を含む
};
```

- イベント終了の画面からは、localStorage に保存した進行中のセッションを書き出す。結果画面からは、履歴の要素の `session` を書き出す
- ファイル名は `libre-shelf-session-{eventDate}.json` とする（例: `libre-shelf-session-2026-12-30.json`）
- 書き出しのボタン「ファイルに書き出す」は、イベント終了の画面（[イベント終了.md](イベント終了.md)）と結果画面に置く

## ファイルからの読み込み

書き出したセッションのファイルを読み込んで、履歴に足せるようにする。読み込む操作は、データの管理の画面に置く（[../データの管理.md](../データの管理.md)）。

- 読み込んだセッションは、新しい `id` と、読み込んだ時刻の `savedAt` を付けて、履歴に足す。同じファイルを 2 回読み込んだら、2 件になる
- 次のときは、何も変えずに、読み込めなかったことを表示する。文言はデータの管理の画面の仕様に書く
  - ファイルが JSON でない
  - `format` が `"libre-shelf-session"` でない
  - `version` が `1` でない
  - `session` の `schemaVersion` が今のスキーマ（セッションのデータ.md）でない
  - `session` が今のスキーマの型（`shared/entity/event/v2026-11-21/libre-event-session.ts` の zod のスキーマ）の検証に通らない
