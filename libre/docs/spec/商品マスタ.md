# 商品マスタ

頒布する商品を、端末の localStorage に登録しておく。即売会のおしながきは、ここから商品を選んで作る（[即売会/前日準備.md](即売会/前日準備.md)）。画面のパスは `/items` で、メニューの「商品管理」から開く。

## データ

localStorage のキー `items` に、商品の配列を JSON で持つ。

```typescript
type Item = {
  item_id: string;          // 13 桁のコード。商品ごとに一意
  product_name: string;     // 商品名。必須
  publisher_name: string;   // サークル（発行者名）。必須
  class: string;            // 分類。必須。選択肢は「オリジナル」「パロディ」
  type: string;             // 種類。必須。選択肢は src/pages/items/constants.ts の TYPE_OPTIONS
  genre_code?: string | null;       // ジャンルコード
  price?: number | null;            // 標準の価格。0 以上の整数
  sample_image_url?: string | null; // サンプル画像の URL
};
```

- 必須と任意は、isdn.jp で ISDN の発行に要る項目に合わせている
- 一覧は登録した順に並べる。編集や読み込みで上書きした商品は、元の位置のままにする
- localStorage への書き込みに失敗したら（容量が足りないなど）、商品マスタを変えずに「商品を保存できませんでした。端末の空き容量を確認してください。」と表示する
- localStorage の値が読めない（JSON として壊れている、形が違う）ときは、商品が 0 件のものとして表示し、値は書き換えない。上書きされて失われないようにするため、値が読めないあいだは追加、編集、削除、書き出し、読み込みをできなくし、「保存されている商品のデータを読み込めませんでした。データを上書きしないように、追加、変更、読み込みを止めています。」と表示する。値を直す操作はアプリに置かない

## 商品の登録

### ISDN から登録する

1. ISDN（13 桁の数字）を入力して、追加のボタンを押す。入力が 13 桁の数字になった時点でも、ボタンを押したときと同じように追加する。全角の数字は半角にして扱う
2. サーバの `GET /api/v1/isdn/{isdn}` で、isdn.jp に登録された情報を取得する
3. 取得した情報（商品名、サークル、分類、種類、ジャンルコード、価格、サンプル画像の URL）を、`item_id` を ISDN にして商品マスタに足す。分類と種類は isdn.jp の値をそのまま入れ、選択肢にない値でもそのまま残す

- 空のまま押したら「ISDNを入力してください。」、数字以外を含むなら「ISDNは数字のみで入力してください。」と、下の取得の失敗と同じアラートに表示する。桁数や先頭の 3 桁は画面では確かめず、isdn.jp に登録がなければ取得の失敗として扱う
- すでに同じ `item_id` の商品があれば、isdn.jp から取得せず、足さずに「この商品はすでに登録されています。」と表示する
- 取得に失敗したら、商品マスタに足さず、入力欄の ISDN を残して、失敗の理由に合わせて次のように表示する。`{手入力の欄}` は、ISDN を持たない商品を登録する欄を開く操作の名前で、商品管理の画面ではカードの見出しの「新規商品を追加」、即売会のおしながきのダイアログ（[即売会/レジ.md](即売会/レジ.md)）では切り替えの「手入力で登録」にする

  | 失敗の理由 | 文言 |
  | --- | --- |
  | 応答が `404`（isdn.jp に登録がない） | ISDNが見つかりませんでした。番号を確認して、もう一度追加してください。 |
  | 応答が `502`（isdn.jp から取得できない） | ISDNの情報を取得できませんでした。時間をおいて、もう一度追加してください。 |
  | 応答が `400`（isdn.jp の情報が `Item` の形でない）、または `200` の応答の中身が上の `Item` の形でない | ISDNの情報が足りません。「{手入力の欄}」から追加してください。 |
  | 応答が `422`（ISDN の形でない） | ISDNではありません。入力し直してください。 |
  | 上のどれでもない、成功でない応答（`500` など） | 商品を追加できませんでした。時間をおいて、もう一度追加してください。 |
  | 応答が返らない（オフライン、通信が切れた） | 商品を追加できませんでした。通信状態を確認して、もう一度追加してください。 |

  どの文言も、入力欄の行の下のアラートに出す。アラートの出し方は、[デザイン/index.md](デザイン/index.md) の「処理の失敗」に従う。この欄では、入力の検証のエラーも、`Field` のエラーの理由（入力欄のすぐ下の文字）としては出さない。`Field` の `error` は渡さない。入力欄と「追加」「カメラ」のボタンは、どの画面幅でも横に並べ、上端と下端をそろえる。応答のステータスコードと中身は画面に出さず、ブラウザのコンソールに出す（[デザイン/index.md](デザイン/index.md) の「文言と書式」）

- ISDN の取得はオンラインでだけ使える。オフラインでもボタンは押せ、応答が返らない失敗として扱う

### 新しい商品を登録する

ISDN を持たない商品は、商品名、サークル、分類、種類、ジャンルコード、価格、サンプル画像の URL を入力して登録する。

- `item_id` には 271 で始まるインストアコードを、端末の中で生成して付ける（`shared/entity/items/item_id.ts` の `generateItemId`）。生成したコードがすでにあれば、生成し直す
- 必須の欄が空なら、欄ごとに「商品名を入力してください。」「サークルを入力してください。」「分類を選択してください。」「種類を選択してください。」と表示し、登録しない
- 価格は 0 以上の整数で、空なら持たない

## 一覧と編集

- 一覧の表には商品ごとに商品ID、商品名、サークル、価格の列を置く。価格がなければ「-」と表示する。商品がなければ「商品がありません。「新規商品を追加」から追加できます。」と表示する
- 行を押すと、詳細のダイアログを開く。ダイアログで、新しい商品を登録するときと同じ欄を、同じ検証と文言で編集して保存できる。`item_id` は変えられない
- ISDN の商品（先頭が 278 か 279）は、詳細のダイアログで「ISDNから取得」を押すと、`GET /api/v1/isdn/{isdn}` で取得し直した情報で上書きする。取得に失敗したら上書きせず、「商品の情報を取得できませんでした。通信状態を確認して、もう一度取得してください。」と表示する
- 「ISDNから取得」で上書きするときの書き込みの失敗は、上の「データ」の書き込みの失敗と同じに扱う
- 編集や削除の対象の商品が、商品マスタにもうないときは、「商品が見つかりませんでした。」と表示する
- 削除のボタンを押したら、確認のダイアログ（見出し「商品の削除」、本文「以下の商品を削除しますか？　この操作は元に戻せません。」、商品名、サークル、価格）で確かめてから消す
- 進行中の即売会のおしながきに入っている商品も、履歴の記録に出てくる商品も消せる。セッションは商品名とサークル名を写して持つので、消しても記録の表示は変わらない（[即売会/セッションのデータ.md](即売会/セッションのデータ.md)）

## 書き出しと読み込み

端末のデータが消えたときや、別の端末へ移すときのために、商品マスタを JSON ファイルに書き出し、読み込めるようにする。

- 「書き出す」ボタンで、次の形の JSON を `libre-shelf-items-YYYY-MM-DD.json`（日付は書き出した日）としてダウンロードさせる

```json
{
  "format": "libre-shelf-items",
  "version": 1,
  "items": [ /* Item の配列 */ ]
}
```

- 「読み込む」ボタンでファイルを選ばせ、中の商品を商品マスタに足す
  - `item_id` が同じ商品があれば、ファイルの内容で上書きする。ファイルにない商品は残す
  - ファイルの中で同じ `item_id` が 2 回以上出てきたら、あとのものを使う
  - ファイルが JSON でない、`format` が `"libre-shelf-items"` でない、`version` が `1` でない、商品の形が上の `Item` と合わない（必須の項目が文字列でないか空白だけである、`item_id` が 13 桁の数字でない、`price` が 0 以上の整数でも null でもないなど。分類と種類は選択肢にない値でも受け付ける）ときは、何も変えずに「ファイルを読み込めませんでした。「書き出す」で保存したファイルを選んでください。」と表示する
  - ファイルにあって商品マスタになかった商品は、一覧の末尾に、ファイルの順で足す
  - 「書き出す」と「読み込む」のボタンは、一覧の表の上の、右寄せのボタンだけの行に置く。この行は、2 行のアラートが入る高さを、失敗がないときも取っておく
  - 読み込みに失敗したとき（形が違う、書き込みに失敗した）は、ボタンの行の、「書き出す」の左に destructive のアラートで文言を出す。もう一度読み込むときに消す（[デザイン/index.md](デザイン/index.md) の「処理の失敗」）
  - 読み込めたときは、上書きした商品は一覧の変化では分からないので、トーストで文言を出す（[デザイン/index.md](デザイン/index.md) の「成功」）
  - 読み込めたら「N 件の商品を読み込みました。」と表示する。N は、ファイルにある商品の件数から、同じ `item_id` の重なりを除いた数で、上書きした商品も数える

## ISDN の中継 API

`GET /api/v1/isdn/{isdn}` は、isdn.jp の `https://isdn.jp/xml/{isdn}` を取得し、上の `Item` の形にして返す。isdn.jp は CORS を許していないので、ブラウザからは直接取得できず、サーバで中継する。

- サーバは取得した情報を保存しない
- isdn.jp の XML のうち、`Item` に使わない要素は確かめない。使わない要素がなくても失敗にしない
- `sample-image-uri` が URL として解釈できなければ（空も含む）、`sample_image_url` を持たないものとして返す
- 値の前後の空白は取り除かず、isdn.jp の値のまま返す
- isdn.jp の XML の、`Item` の必須の 4 項目に当たる要素（`product-name`、`publisher-name`、`class`、`type`）がないか、空白だけなら、応答の形が違うものとして扱う
- isdn.jp に登録がなければ `404` を返す。isdn.jp に接続できないか、isdn.jp が 404 以外のエラーを返したら `502` を返す。isdn.jp の応答の形が違えば `400` を返す
- `{isdn}` が ISDN の形（`shared/entity/items/item_id.ts` の `isISDN`）でなければ、入力の検証に失敗したものとして `422` を返す（OpenAPI のドキュメントに載る）
- 「ISDN から登録する」の画面は、応答のステータスコードで失敗の理由を見分ける。詳細のダイアログの「ISDNから取得」は、成功以外のどの応答も、取得の失敗として扱う
- ここでいうサーバは、アプリのファイルを配る Cloudflare Workers の Worker である
