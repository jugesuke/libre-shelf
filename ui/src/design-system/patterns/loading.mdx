# 読み込み中と処理中

データを読み込んでいる間と、操作を処理している間の見せ方です。

| 場面 | 見せ方 |
|---|---|
| ボタンを押して処理している間 | ボタンのラベルをローダーに置き換える |
| テーブルを読み込んでいる間 | 行がないときの 1 行と同じ場所に、ローダーを出す |
| テーブル以外を読み込んでいる間 | 中身がないときの表示と同じ高さの場所に、ローダーを出す |
| 表示しているテーブルを読み込み直している間 | 中身の行を薄くし、ローダーを重ねる |

ローダーは lucide-react の `LoaderCircle` で、20px、線の太さは 2.5 です。押した直後や読み込みを始めた直後から出し、出すのを遅らせません。

## 処理中のボタン

処理中のボタンは幅を変えずに、ラベルを隠してローダーに置き換えます。処理中は押せないようにし、`aria-busy` を付けます。

- 枠線は破線にする。背景、枠線、ローダーの色はボタンの種類ごとに決める（[ボタン](?path=/docs/ui-button--docs)の「処理中」）。

<Canvas of={LoadingStories.ProcessingButton} />

### なぜラベルを「登録中...」に変えないのか

ラベルの長さが変わると、ボタンの幅が変わり、隣の要素の位置がずれるためです（[原則](?path=/docs/原則--docs)）。

### なぜローダーを遅らせて出さないのか

遅らせると、押せないのにボタンの見た目が変わらない時間ができ、押せたのかどうかが分からなくなるためです。

## テーブルの読み込み中

テーブルの見出しの行を表示し、行がないときの 1 行と同じ場所の中央に、ローダーを出します。読み込みが終わると、受け取った行の数だけテーブルが下へ広がります。

<Canvas of={LoadingStories.TableLoading} />

### なぜ 1 行ぶんなのか

行がないときの表示と同じで、行 1 つと同じ高さなので、結果が空のときと 1 行のときは高さが変わらず、2 行以上のときは下へ広がります。行にボタンや入力欄があるテーブルでは、ボタンのある行と同じ高さにします（[テーブル](?path=/docs/ui-table--docs)）。読み込み中に大きな場所を取ると、結果が少ないときに縮んでから広がります。

## テーブル以外の読み込み中

テーブルと同じく、中身がないときの表示と同じ高さの場所の中央に、ローダーを出します。

<Canvas of={LoadingStories.NonTableLoading} />

## 読み込み直すとき

登録のあとに一覧を取得し直すときなど、表示しているテーブルを読み込み直すときは、前の中身を出したまま、見出しの行を除いた中身の行を薄くします（不透明度 40%、操作できなくする）。中身の行の範囲の真ん中に、フォーカスリングと同じ色のローダーを重ね、終わったら新しい中身に入れ替えます。

<Canvas of={LoadingStories.Reload} />

### なぜ見出しの行を薄くしないのか

読み込み直しても、見出しの行は変わらないためです。
