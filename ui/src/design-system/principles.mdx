# 原則

[コンセプト](?path=/docs/コンセプト--docs)のもとで、画面を作るときに守るルールです。

## 同じ機能には、同じデザインを使う

開閉する領域や、操作ボタンを並べる箇所のように、機能が同じものは、どの画面でも同じコンポーネントで作ります。画面ごとにデザインが違うと、利用者は画面ごとに使い方を覚え直すことになるためです。

## プライマリカラーを画面ごとに変えて、いまどの画面にいるかを示す

即売会、商品管理などの画面ごとにプライマリカラーの値を変えます。プライマリカラーは、メニュー、画面上端の帯、その画面の主要な操作に使います。

## 操作の重要度は、ボタンの種類で示す

画面でいちばん重要な操作はプライマリカラーで塗ったボタン（primary）にします。ほかの操作は灰色のボタン（secondary）、使用頻度の低い操作はテキストだけのボタン（text）にします。ボタンの大きさは重要度によって変えません。

## 表示の状態で、レイアウトをずらさない

エラーメッセージの表示やボタンの処理中など、表示の状態が変わっても、ほかの要素の位置が動かないようにします。アラートは、行の高さをあらかじめ取っておいた場所に置くか、ほかの要素の上に浮かせて重ねます（[フィードバック](?path=/docs/デザインパターン-フィードバック--docs)）。

読み込みが終わり、データを表示したことによる変化は除きます。データの量は読み込みが終わるまで分からず、ずれを避けられないためです。

## 誰にでも読める色と大きさにする

文字とコンポーネントのコントラストは、[WCAG 2.2](https://www.w3.org/TR/WCAG22/) の AA に従います。

- 文字と背景のコントラスト比は 4.5:1 以上。24px 以上の文字か、約 18.7px 以上の太字は 3:1 以上でよい（達成基準 1.4.3）。
- 入力欄の枠線や選択状態のインジケーターなど、コンポーネントとその状態を見分けるのに必要な部分は、隣接する色と 3:1 以上（達成基準 1.4.11）。
- 無効状態のコンポーネントはどちらの基準の対象にもならない。

操作できる要素は、WCAG 2.2 の AA（24px 以上）より大きい、高さ 32px 以上にします（[ターゲットサイズ](?path=/docs/基本デザイン-ターゲットサイズ--docs)）。
